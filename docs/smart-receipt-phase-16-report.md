# Отчёт по модулю Smart Receipt (Фаза 16)

## Дата: 2026-09-13
## Ветка: feature-phase-16

## Назначение

Трассирующая пуля модуля документов: рабочий путь «завершение сделки →
автоформирование чека из договора → локальная генерация PDF для скачивания».
Проверка базовой архитектуры хранения документов и генерации чека НПД.

## Что реализовано

| Задача | Реализация |
|--------|------------|
| Isar-коллекция `Document` | `lib/data/models/document.dart`: тип (`receipt`/`act`/`contract`), статус, привязки к договору (`contractDraftId`) и транзакции (`transactionId`), контрагент, сумма, дата, услуга, реквизиты исполнителя |
| Репозиторий документов с шифрованием | `DocumentRepository` + `IsarDocumentRepository` (`lib/data/repositories/`): шифрование персональных полей AES-256 через `DatabaseEncryptionService`, как в транзакциях и черновиках |
| Регистрация схемы и миграции | `DocumentSchema` добавлена в `AppDatabase.open` (`lib/data/database.dart`); Isar выполняет миграцию автоматически при добавлении коллекции |
| Генерация чека с автозаполнением | `Receipt` + `ReceiptGenerator` (`lib/domain/documents/receipt.dart`): реквизиты исполнителя из профиля ИП, поля (услуга, сумма, дата, ИНН покупателя) из договора, приоритет транзакции |
| PDF-версия чека по формату ФНС | `ReceiptPdfService` (`lib/data/pdf/receipt_pdf_service.dart`): локальная генерация A4, поля 20 мм, кириллица через встроенный Roboto, признак расчёта, ИНН сторон |
| Автоформирование при завершении сделки | `DealCompletionService` (`lib/domain/documents/deal_completion_service.dart`) и экран `DealCompletionScreen` (`lib/presentation/documents/`): предзаполнение, запись дохода, сохранение чека в архив, предпросмотр PDF |
| Интеграция с архивом договоров | Действие «Завершить сделку» в `ContractArchiveScreen` для подписанных договоров; проброс зависимостей через `HomeShell` и `main.dart` |

## Рабочий путь

1. В архиве договоров у подписанного договора выбирается «Завершить сделку».
2. `DealCompletionScreen` предзаполняет поля чека из профиля ИП и договора
   (`ReceiptGenerator`), поля остаются редактируемыми.
3. По кнопке «Завершить сделку» при необходимости доход записывается в дашборд
   (`TransactionRepository.add`), затем чек сохраняется в архив
   (`DealCompletionService.saveReceipt`).
4. PDF-версия чека генерируется локально в фоновом изоляте и открывается лист
   предпросмотра с шарингом и сохранением файла.

## Общий PDF-слой

Для переиспользования инфраструктуры договоров и чеков введены общие типы
`GeneratedPdf` (`lib/data/pdf/generated_pdf.dart`) и `PdfFonts`
(`lib/data/pdf/pdf_fonts.dart`). Существующие `GeneratedContractPdf` и
`ContractPdfFonts` стали их псевдонимами — совместимость сохранена.

## Критерии готовности PRD

| Критерий | Проверка |
|----------|----------|
| Чек генерируется автоматически при завершении сделки | `receipt_smoke_test`, `deal_completion_screen_test` |
| Время формирования чека < 10 секунд | `receipt_pdf_service_test` |
| Формат чека (поля ФНС) | `receipt_generator_test`, `receipt_pdf_service_test` |
| Шифрование БД AES-256 | `document_repository_test` (шифрование персональных полей) |

Остальные критерии PRD относятся к последующим фазам: акт (17), deep link (18),
архив с поиском (19), привязка к транзакциям и финализация (20).

## Ручная проверка на реальном устройстве

1. Отметить договор подписанным в архиве.
2. Выбрать «Завершить сделку», проверить предзаполненные реквизиты.
3. Завершить сделку и убедиться, что открылся PDF-чек и доход появился в
   дашборде.
4. Открыть PDF, проверить читаемость кириллицы и корректность полей.
