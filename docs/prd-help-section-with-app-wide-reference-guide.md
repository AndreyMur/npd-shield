# PRD: Раздел «Помощь» со справочником по всему приложению

**Дата**: 2026-09-18
**Статус**: Draft

## Цель

Дать предпринимателю единый встроенный справочник, из которого он за 1–2 минуты поймёт, как пользоваться каждым разделом приложения, и сможет самостоятельно выполнить нужное действие без обращения в поддержку.

## Обзор продукта

Своё дело — офлайн-приложение для ИП на НПД / самозанятых, которое объединяет 11 рабочих разделов: Дашборд, Операции, Клиенты, Счета, Шаблоны, Договоры, Документы, Проверка (Risk Shield), Уведомления, Отчёты, Настройки. Сейчас обучающий контент разбросан: онбординг показывается один раз, подсказки «?» есть только в Risk Shield, инструкции по «Мой налог» — в отдельном экране. Новый пользователь не понимает назначение разделов и не знает, с чего начать.

Фича добавляет в приложение отдельный раздел **«Помощь»** — структурированный справочник по всем разделам приложения с поиском, оглавлением и пошаговыми инструкциями.

## Целевая аудитория

- Новый пользователь на этапе первого запуска и первых недель работы.
- Опытный пользователь, который забыл, как выполнить конкретное действие (например, отметить частичную оплату счёта или завершить сделку).
- Пользователь, которому нужно быстро найти ответ без выхода из приложения.

## Пользовательские сценарии

- Пользователь впервые открыл приложение -> видит раздел «Помощь» в навигации и может прочитать обзор разделов, чтобы понять, с чего начать.
- Пользователь не понимает назначение раздела «Счета» -> открывает «Помощь», находит статью «Счета» -> читает пошаговую инструкцию по созданию и оплате счёта.
- Пользователь ищет по ключевому слову «договор» -> получает список релевантных статей справочника и переходит в нужную.
- Пользователь забыл, как отметить частичную оплату -> находит статью, следует шагам, возвращается к работе.
- Пользователь хочет понять, что делает функция «Проверка» -> читает статью с описанием рисков и порядка проверки договора.
- Пользователь не уверен в каком-то шаге -> открывает статью «Частые вопросы» и находит ответ.

## Функциональные требования

### Размещение и навигация

- «Помощь» — отдельный пункт в основной навигации приложения (12-й раздел), доступный на широких экранах (NavigationRail) и на мобильных (Drawer).
- Иконка раздела — однозначно узнаваемая (help), с текстовой подписью в соответствии с текущими паттернами навигации.
- Раздел открывается как обычный экран через `IndexedStack`-шелл, без отдельного роутера.

### Структура справочника

- Главный экран «Помощь» содержит:
  - строку поиска по справочнику;
  - оглавление/список разделов (аккордеон или список карточек);
  - блок «С чего начать» для новых пользователей.
- Справочник покрывает **все 11 разделов** приложения, а также ключевые сквозные сценарии: онбординг, «Мой налог», формирование PDF, резервное копирование и восстановление, шаблоны договоров, Risk Shield.
- Каждая статья раздела содержит:
  - краткое описание — что это и зачем (1–3 предложения);
  - пошаговую инструкцию «как пользоваться» (нумерованные шаги);
  - список частых вопросов/подсказок (при наличии).
- Для каждого раздела указаны смежные материалы: ссылки на связанные статьи (например, «Счета» -> «Операции», «Документы»).

### Поиск

- Поиск работает по заголовкам статей и их содержимому.
- Результаты поиска показывают название статьи и раздел, к которому она относится; тап открывает статью.
- При пустом результате показывается понятное сообщение и предложение посмотреть оглавление.
- Поиск выполняется мгновенно по мере ввода и работает офлайн.

### Контент

- Весь контент справочника встроен в приложение и доступен офлайн.
- Тексты на русском языке, соответствуют фактическому поведению текущей версии приложения.
- Контент структурирован так, чтобы его можно было дополнять при добавлении новых разделов без изменения логики экрана.

### Обратная связь

- В статьях сохраняется действующий дисклеймер о том, что материалы носят справочный характер и не заменяют консультацию специалиста.
- На экране «Помощь» доступна точка входа в «О приложении» (версия, описание).

## Нефункциональные требования

- **Офлайн-доступность**: справочник полностью работает без интернета.
- **Производительность**: открытие раздела и поиск — без заметных задержек (отклик поиска < 200 мс на типовом устройстве).
- **Адаптивность**: корректное отображение на мобильных и широких экранах в соответствии с текущими паттернами приложения.
- **Согласованность**: визуальный стиль, шрифты и компоненты соответствуют дизайн-системе приложения (Material 3, кастомные токены).
- **Поддерживаемость**: добавление новой статьи/раздела не требует правок навигационной логики.

## Дизайн и UX

- Стиль согласован с существующими экранами (карточки, аккордеоны, поиск).
- Навигация внутри справочника: главный экран -> статья -> связанные статьи; всегда доступен возврат к оглавлению.
- Тексты короткие и практичные: описание, шаги, подсказки.
- Поиск расположен в верхней части экрана и доступен без прокрутки.
- Состояния: пустой поиск, нет результатов, длинная статья (прокрутка).

## Не в скоупе

- Полноценная система локализации (i18n) справочника — только русский язык, как и остальное приложение.
- Загрузка/обновление контента с сервера без релиза приложения.
- Скриншоты, видео, анимации и интерактивные туры.
- Обратная связь/тикеты в поддержку из раздела «Помощь».
- Контекстные кнопки «?» на каждом экране, ведущие в соответствующую статью.
- Персонализация справочника под действия конкретного пользователя.
- Публикация справочника за пределами приложения (сайт, база знаний).

## Технические ограничения

- В приложении нет i18n-фреймворка: все строки захардкожены на русском; справочник следует этому же подходу.
- Нет именованных маршрутов/роутера: раздел встраивается в существующий `IndexedStack`-шелл (`home_shell.dart`), подэкраны открываются через `Navigator.push`.
- Приложение офлайн-первое, без бэкенда — контент поставляется вместе с приложением (assets/код).
- Контент должен синхронизироваться с фактическим поведением разделов; при изменении функциональности статьи требуют обновления в том же релизе.
- Платформы: Android, iOS, Web, Windows.

## Риски и предположения

- **Риск**: контент быстро устаревает при изменении UI/функций -> требуется процесс ревью справочника в рамках релиза.
- **Риск**: чрезмерно объёмные статьи снижают полезность -> ограничиваем формат «описание + шаги + подсказки».
- **Предположение**: пользователю достаточно текстовых инструкций без скриншотов и видео.
- **Предположение**: 11 текущих разделов — стабильный набор на момент релиза фичи.

## Критерии успеха (KPI)

- Доля пользователей, открывших раздел «Помощь», от активных пользователей.
- Доля успешных поисков (поиск с переходом в статью) от общего числа поисков.
- Снижение числа повторных обращений к обучающим материалам онбординга.
- Среднее время до первой самостоятельной операции у новых пользователей.

- [ ] Каждая статья включает описание и пошаговую инструкцию.
- [ ] Поиск по справочнику работает мгновенно и находит статьи по заголовку и содержимому.
- [ ] Пустой результат поиска отображает понятное сообщение.
- [ ] Из статьи доступны переходы к связанным статьям.
- [ ] Есть блок «С чего начать» для новых пользователей.
- [ ] Раздел и поиск полностью работают без подключения к интернету.
- [ ] Дисклеймер о справочном характере материалов отображается в статьях.
- [ ] Экран корректно отображается на мобильном и широком форм-факторах.
