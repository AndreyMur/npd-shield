# Отчёт по модулю Smart Receipt (Фаза 17)

## Дата: 2026-09-13
## Ветка: feature-phase-17

## Назначение

Формирование акта выполненных работ: автозаполнение из договора и чека,
подписи сторон для распечатки, автосохранение черновика и связь акта с
договором и чеком в единой карточке документа.

## Что реализовано

| Задача | Реализация |
|--------|------------|
| Акт выполненных работ с автозаполнением | `Act` + `ActGenerator` (`lib/domain/documents/act.dart`): описание работ из предмета договора, результат (значение по умолчанию), сумма, дата выполнения, реквизиты сторон из профиля ИП и договора/чека |
| Подписи сторон и привязки | Поля `executorSignatory` и `customerSignatory` в `Act`; привязка к договору (`contractDraftId`) и к чеку (`receiptDocumentId`). PDF-акт выводит блок «Подписи сторон» с линиями для подписи (`ActPdfService`) |
| Расширение модели документа | `Document` (`lib/data/models/document.dart`) получил `result`, `executorSignatory`, `customerSignatory`, индексированную привязку `receiptDocumentId`; шифрование новых персональных полей AES-256 в `IsarDocumentRepository`; запрос `getByReceiptDocumentId` |
| Единая карточка документа | `DocumentCard` (`lib/presentation/documents/document_card.dart`): тип, статус, контрагент, сумма и дата документа плюс связи с договором и чеком |
| Автосохранение при создании документа | `ActService` (`lib/domain/documents/act_service.dart`) и экран `ActScreen` (`lib/presentation/documents/act_screen.dart`): черновик сохраняется сразу при открытии и обновляется с задержкой при изменении полей; индикатор «Сохранение… / Сохранено» |
| PDF-версия акта | `ActPdfService` (`lib/data/pdf/act_pdf_service.dart`): локальная генерация A4, поля 20 мм, кириллица через Roboto, шапка «к договору», таблица работ, результат и подписи сторон |
| Интеграция с архивом договоров | Действие «Создать акт» в `ContractArchiveScreen` для подписанных договоров; акт автоматически привязывается к последнему чеку по договору |

## Рабочий путь

1. В архиве договоров у подписанного договора выбирается «Создать акт».
2. `ActScreen` предзаполняет поля из профиля ИП, договора и последнего чека
   (`ActGenerator`), автоматически привязывает акт к договору и чеку.
3. Черновик акта сразу сохраняется в архив (`ActService`), дальнейшие
   изменения полей сохраняются автоматически.
4. По кнопке «Сформировать акт» документ переводится в статус «Сформирован»,
   PDF генерируется локально и открывается лист предпросмотра.

## Критерии готовности PRD

| Критерий | Проверка |
|----------|----------|
| Акт корректно заполняется из данных договора | `act_generator_test`, `act_screen_test` |
| Подписи сторон (поля для распечатки) | `act_generator_test`, `act_pdf_service_test`, `act_screen_test` |
| Привязка акта к договору и чеку | `act_screen_test`, `act_smoke_test`, `document_repository_test` |
| Автосохранение при создании документа | `act_screen_test` (создание и обновление без дублей) |
| Время формирования PDF < 10 секунд | `act_pdf_service_test` |

Остальные критерии PRD относятся к последующим фазам: deep link (18),
архив с поиском (19), привязка к транзакциям и финализация (20).

## Ручная проверка на реальном устройстве

1. Отметить договор подписанным и завершить сделку, чтобы появился чек.
2. Выбрать «Создать акт», проверить предзаполненные поля и подписи.
3. Изменить поле и убедиться, что индикатор показывает «Сохранено», а в
   архиве нет дублей акта.
4. Сформировать акт, открыть PDF, проверить читаемость кириллицы, блок
   подписей и связь с договором и чеком.
