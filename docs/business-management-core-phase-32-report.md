# Отчёт по модулю Business Management Core (Фаза 32)

## Дата: 2026-09-16
## Ветка: feature-phase-32

## Назначение

Интерфейс клиентов (Модуль 3): пользователь ведёт справочник контрагентов
(список, поиск, создание, редактирование, удаление), открывает карточку клиента
с историей операций и документов и выбирает клиента из справочника при создании
операции, договора и чека.

## Что реализовано

| Задача | Реализация |
|--------|------------|
| Экран справочника клиентов | `lib/presentation/clients/clients_screen.dart`: список карточек, поиск по наименованию и ИНН, создание (FAB), редактирование, удаление с подтверждением и отменой. Пустое состояние и состояние ошибки с повтором |
| Форма клиента | `lib/presentation/clients/client_form_screen.dart`: наименование (обязательно), ИНН (10/12 цифр), тип (юрлицо/ИП или физлицо), контакты, заметки. Возвращает сохранённого клиента |
| Карточка клиента | `lib/presentation/clients/client_details_screen.dart`: реквизиты, история операций (по `Transaction.clientId`) и документов (по `Document.clientId`), кнопка редактирования, пустые состояния |
| Выбор клиента | `lib/presentation/clients/client_picker.dart`: переиспользуемый лист выбора с поиском и созданием нового клиента «на лету». Используется в форме операции, мастере договора и экране завершения сделки |
| Выбор в операции | `TransactionFormScreen` получил `clientRepository`: выбор клиента заполняет контрагента и ИНН, сохраняет `clientId`; ручной ввод сбрасывает связь. `OperationsScreen` пробрасывает справочник |
| Выбор в договоре | `ContractWizardScreen` получил `clientRepository`: на шаге «Заказчик» выбор заполняет наименование и ИНН; `clientId` сохраняется в черновике (`ContractDraft.clientId`) и в записи архива документов |
| Выбор в чеке | `DealCompletionScreen` получил `clientRepository`: выбор покупателя заполняет наименование и ИНН; `clientId` записывается в транзакцию и в чек (`Receipt.clientId` → `Document.clientId`) |
| Навигация | `HomeShell` получил раздел «Клиенты»; `main.dart` передаёт `ClientRepository` в приложение и оболочку |
| Архив документов | `DocumentRepository.getByClientId` — выборка документов клиента для карточки |

## Рабочий путь

1. В разделе «Клиенты» пользователь видит справочник, ищет по наименованию и
   ИНН, создаёт и редактирует карточки.
2. Нажатие на карточку открывает карточку клиента с историей операций и
   документов; карточку можно отредактировать прямо оттуда.
3. При создании операции, договора или чека кнопка «Выбрать из справочника»
   подставляет реквизиты клиента и сохраняет связь по `clientId`. Если клиента
   нет, его можно создать прямо из листа выбора.
4. Связь хранится идентификатором: удаление клиента не затрагивает операции,
   документы и договоры.
