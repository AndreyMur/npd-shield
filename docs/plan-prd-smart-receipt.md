# Plan: Smart Receipt & Document Flow

**PRD:** prd-smart-receipt
**Дата:** 2026-08-31

## Фазы реализации

### Фаза 16: Tracer Bullet — Модель данных, генерация чека и PDF

**Цель:** Рабочий путь «завершение сделки → автоформирование чека из договора → PDF для скачивания». Проверка основной гипотезы и базовой архитектуры хранения документов.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [x] Создать Isar-коллекции `Document` (тип, договор, контрагент, сумма, дата, статус, привязка к транзакции) с миграциями и шифрованием БД (AES-256).
- [x] Реализовать генерацию чека с автозаполнением реквизитов из профиля ИП и полями (наименование услуги, сумма, дата, ИНН покупателя), привязкой к договору.
- [x] Реализовать генерацию PDF-версии чека по формату ФНС для НПД (локально, кириллица через Roboto).
- [x] Реализовать автоформирование чека при завершении сделки (данные из договора/транзакции).
- [x] Написать unit-тесты для генерации чека (автозаполнение, корректность полей, формат) и widget-тесты для экрана завершения сделки; интеграционные тесты генерации PDF.
**Когда готова:** При завершении сделки автоматически формируется чек с реквизитами из профиля и привязкой к договору; PDF-версия генерируется локально; время формирования чека < 10 секунд; БД шифруется AES-256.

### Фаза 17: Акт выполненных работ

**Цель:** Автоматическое формирование акта выполненных работ из данных договора с подписями сторон.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [x] Реализовать формирование акта выполненных работ с автозаполнением из договора (описание работ, результат, сумма, дата выполнения).
- [x] Добавить поля подписей сторон (для распечатки) и привязку акта к договору и чеку.
- [x] Связать акт с чеком и договором в единой карточке документа.
- [x] Обеспечить автосохранение при создании документа.
- [x] Написать unit-тесты для заполнения акта из договора и widget-тесты для экрана акта (корректные поля, подписи, привязки).
**Когда готова:** Акт выполненных работ корректно заполняется из данных договора, содержит подписи сторон и привязан к договору и чеку; данные сохраняются автоматически.

### Фаза 18: Deep link на «Мой налог»

**Цель:** Переход из приложения в «Мой налог» с предзаполненными данными чека и fallback при отсутствии приложения.
**Затрагивает:** frontend (Flutter)
**Задачи:**
- [ ] Реализовать формирование deep link URL с параметрами: сумма, тип клиента (юрлицо/физлицо).
- [ ] Реализовать проверку установки приложения «Мой налог» и открытие deep link (LaunchMode.externalApplication).
- [ ] Реализовать fallback — копирование данных в буфер обмена при отсутствии приложения.
- [ ] Добавить инструкцию по ручному вводу данных в «Мой налог».
- [ ] Написать unit-тесты для формирования URL и widget-тесты для экрана deep link (установлено/не установлено, fallback, инструкция).
**Когда готова:** Deep link корректно формирует URL и открывает приложение «Мой налог» с переданными данными; при отсутствии приложения данные копируются в буфер и показывается инструкция по ручному вводу.

### Фаза 19: Архив документов с поиском и фильтрацией

**Цель:** Единый архив всех документов (чеки, акты, договоры) с группировкой, сортировкой и быстрым поиском.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [ ] Реализовать экран архива со списком всех документов (чеки, акты, договоры) с иконками по типу и группировкой по контрагентам.
- [ ] Реализовать сортировку по дате, сумме, типу документа и фильтрацию по типу и статусу.
- [ ] Реализовать поиск по наименованию контрагента, сумме, дате с автодополнением.
- [ ] Реализовать карточку документа: Bottom sheet с деталями и кнопками «Отправить», «Скачать PDF», «Удалить».
- [ ] Написать unit-тесты для поиска и фильтрации, widget-тесты для экрана архива (поиск < 500 мс по базе 1000 документов, сортировка, фильтры, accessibility для скринридеров).
**Когда готова:** Архив доступен и функционален при 1000+ документах; поиск работает за < 500 мс; группировка, сортировка и фильтрация работают; элементы доступны для скринридеров.

### Фаза 20: Привязка к транзакциям, экспорт и финализация

**Цель:** Связка документов с транзакциями дашборда, экспорт в PDF и подтверждение всех критериев готовности PRD.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [ ] Реализовать автоматическое сопоставление документов с транзакциями из дашборда и визуальную индикацию (значок документа рядом с транзакцией).
- [ ] Реализовать переход к документу из карточки транзакции.
- [ ] Реализовать экспорт всех типов документов (чек, акт, договор) в PDF и шаринг через стандартные приложения.
- [ ] Добавить дисклеймер о том, что документы не имеют юридической силы без ЭЦП.
- [ ] Провести полный smoke-тест (сделка → чек → акт → deep link → архив → поиск → привязка к транзакции) и проверить все критерии готовности PRD (чек < 10 секунд, > 95% сделок, акт корректный, архив 1000+ документов, поиск < 500 мс, accessibility) на реальном устройстве.
**Когда готова:** Документы автоматически сопоставляются с транзакциями и открываются из карточек транзакций; экспорт в PDF и шаринг работают; дисклеймер показан; все критерии готовности PRD выполнены и подтверждены тестами.
