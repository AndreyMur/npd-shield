# Plan: Risk Shield — Юридический Щит

**PRD:** prd-risk-shield
**Дата:** 2026-08-31

## Фазы реализации

### Фаза 11: Tracer Bullet — Модель маркеров и базовый анализ текста

**Цель:** Рабочий путь «загрузка TXT-договора → поиск маркеров риска → показ найденных рисков». Проверка основной гипотезы и архитектуры RiskShieldAnalyzer.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [x] Создать Isar-коллекции `RiskMarker` (pattern, severity, suggestion), `RiskMatch` и `RiskReport` (risks, safetyIndex) с миграциями и шифрованием БД (AES-256).
- [x] Реализовать доменный use case `RiskAnalyzerUseCase`: параллельный поиск по RegExp-паттернам маркеров в тексте договора.
- [x] Добавить базовую базу маркеров риска (критические, средние, низкие) с описание, примером и безопасной альтернативой для каждого.
- [x] Реализовать экран загрузки TXT-файла (до 100 КБ) с автоматическим запуском анализа.
- [x] Написать unit-тесты для `RiskAnalyzerUseCase` (поиск, severities, параллельный анализ) и widget-тесты для экрана загрузки; тесты на граничный размер файла 100 КБ.
**Когда готова:** Пользователь загружает TXT-договор и получает список найденных рисков с уровнями; анализ файла 30 КБ выполняется за < 500 мс; БД шифруется AES-256; тесты покрывают анализатор.

### Фаза 12: Индекс безопасности и визуализация рисков

**Цель:** Пользователь видит индекс безопасности (0-100%) с цветовой шкалой и детальный разбор найденных рисков с безопасными альтернативами.
**Затрагивает:** frontend (Flutter)
**Задачи:**
- [x] Реализовать расчёт индекса безопасности (0-100%) на основе найденных рисков и общего числа маркеров.
- [x] Реализовать визуализацию индекса: круговая диаграмма с процентом и цветовой шкалой (зелёный/жёлтый/красный).
- [x] Реализовать список рисков с цветной полосой слева по уровню, фильтрацию по уровню и раскрывающиеся секции (описание, где найдено, альтернатива).
- [x] Реализовать кнопку «Скопировать безопасную формулировку» для каждого найденного риска.
- [x] Написать unit-тесты для расчёта индекса безопасности (все сценарии: нет рисков, все критические, смешанные) и widget-тесты для визуализации; обеспечить текстовые метки для Accessibility (цвета не единственный способ).
**Когда готова:** Индекс безопасности корректно рассчитывается для всех сценариев и отображается с цветовой шкалой; каждый риск раскрывается с описанием, местом в тексте и копируемой безопасной альтернативой; элемент доступен для скринридеров.

### Фаза 13: История проверок

**Цель:** Сохранять результаты всех проверок и давать доступ к ним для повторного просмотра и удаления.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [x] Реализовать сохранение результатов проверки (договор, дата, индекс безопасности, количество рисков) в историю.
- [x] Реализовать экран истории проверок: список проверенных договоров с датой, индексом и количеством рисков.
- [x] Реализовать повторный доступ к результатам проверки из истории.
- [x] Реализовать удаление проверок из истории.
- [x] Написать unit-тесты для репозитория истории и widget-тесты для экрана истории (сохранение, открытие, удаление).
**Когда готова:** Каждая проверка сохраняется и доступна в истории с датой, индексом безопасности и числом рисков; пользователь может открыть и удалить проверки; история персистентна между сессиями.

### Фаза 14: Полная база маркеров (50+) и точность

**Цель:** Довести базу до 50+ маркеров риска и подтвердить точность > 90% при ложноположительных < 5%.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [ ] Расширить базу маркеров риска до 50+ (критические, средние, низкие) с полным набором полей: RegExp, описание, пример, альтернатива.
- [ ] Сформировать тестовую базу договоров (небезопасные и безопасные образцы) для оценки точности.
- [ ] Прогнать тестовую базу через анализатор и калибровать RegExp-паттерны до точности > 90%.
- [ ] Откалибровать пороги для снижения ложноположительных срабатываний до < 5%.
- [ ] Написать регрессионные тесты на тестовую базу договоров (точность > 90%, ложноположительные < 5%).
**Когда готова:** База содержит 50+ маркеров; на тестовой базе договоров точность обнаружения > 90% и ложноположительные < 5% (подтверждено регрессионными тестами).

### Фаза 15: Интеграция с генератором договоров и финализация

**Цель:** Автоматическая проверка сгенерированных договоров, отображение результатов в карточке договора и подтверждение всех критериев готовности PRD.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [ ] Интегрировать автозапуск проверки после создания договора в генераторе (модуль contract-generator).
- [ ] Отображать результаты Risk Shield в карточке договора с предложением исправлений перед сохранением.
- [ ] Провести полный smoke-тест: генерация договора → автопроверка → просмотр результатов → копирование альтернатив.
- [ ] Включить дисклеймер о том, что Risk Shield не заменяет юридическую консультацию, и инструкцию по конвертации PDF/DOCX в TXT.
- [ ] Устранить выявленные узкие места и проверить все критерии готовности PRD (50+ маркеров, точность, время анализа, индекс, альтернативы, история, accessibility) на реальном устройстве.
**Когда готова:** Сгенерированные договоры автоматически проверяются, результаты доступны в карточке договора с альтернативами; дисклеймер и инструкция показаны; все критерии готовности PRD выполнены и подтверждены тестами.
