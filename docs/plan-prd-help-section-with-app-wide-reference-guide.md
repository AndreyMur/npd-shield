# Plan: Раздел «Помощь» со справочником по всему приложению

**PRD:** prd-help-section-with-app-wide-reference-guide
**Дата:** 2026-09-18

## Фазы реализации

### Фаза 1: Точка входа в «Помощь» (Tracer Bullet)

**Цель:** Добавить раздел «Помощь» в навигацию и открыть минимальный рабочий экран-заглушку, чтобы был сквозной путь от навигации до раздела.
**Затрагивает:** frontend (Flutter presentation, навигация)

**Задачи:**
- [ ] Добавить пункт «Помощь» (иконка help) в `home_shell.dart`: широкие экраны — `NavigationRail`, мобильные — `home_menu_drawer.dart`
- [ ] Встроить экран в существующий `IndexedStack`-шелл как 12-й раздел, без нового роутера
- [ ] Создать `HelpScreen` с базовым скаффолдом: заголовок, поле поиска (неактивное), пустой список разделов
- [ ] Добавить виджет-тест: пункт «Помощь» присутствует в навигации и открывает `HelpScreen`

**Когда готова:** Раздел «Помощь» открывается из навигации и на мобильном (Drawer), и на широком (NavigationRail) экране, отображая базовый скаффолд; тест навигации проходит.

### Фаза 2: Модель и контент справочника

**Цель:** Определить структуру данных статей и наполнить справочник контентом по всем разделам приложения.
**Затрагивает:** frontend (data/domain слой приложения)

**Задачи:**
- [ ] Создать модель статьи: заголовок, привязка к разделу, краткое описание, пошаговые инструкции, частые вопросы/подсказки, связанные статьи
- [ ] Создать встроенный (офлайн) репозиторий контента с возможностью дополнения без правок навигационной логики
- [ ] Наполнить справочник статьями по всем 11 разделам: Дашборд, Операции, Клиенты, Счета, Шаблоны, Договоры, Документы, Проверка (Risk Shield), Уведомления, Отчёты, Настройки
- [ ] Добавить статьи по сквозным сценариям: онбординг, «Мой налог», формирование PDF, резервное копирование и восстановление, шаблоны договоров, Risk Shield
- [ ] Написать тесты данных: все 11 разделов покрыты, у каждой статьи заполнены описание и шаги, связанные статьи ссылаются на существующие материалы

**Когда готова:** Репозиторий контента доступен офлайн и содержит статьи по 11 разделам и сквозным сценариям; тесты полноты и корректности связей проходят.

### Фаза 3: Экран справочника и статья

**Цель:** Дать пользователю рабочий просмотр оглавления, блока «С чего начать» и полной статьи с шагами, подсказками и переходами.
**Затрагивает:** frontend (Flutter presentation)

**Задачи:**
- [ ] Реализовать главный экран «Помощь»: оглавление/список разделов (аккордеон или карточки) и блок «С чего начать» для новых пользователей
- [ ] Реализовать экран статьи: краткое описание, пошаговая инструкция, частые вопросы/подсказки
- [ ] Добавить переходы к связанным статьям из статьи и возврат к оглавлению
- [ ] Добавить в статьи действующий дисклеймер о справочном характере материалов
- [ ] Добавить точку входа в «О приложении» (версия, описание) на экране «Помощь»
- [ ] Написать виджет-тесты: рендер оглавления и блока «С чего начать», открытие статьи, переход по связанным статьям, отображение дисклеймера

**Когда готова:** Пользователь может пройти путь оглавление -> статья -> связанная статья и вернуться к оглавлению; дисклеймер и вход в «О приложении» доступны; тесты проходят.

### Фаза 4: Поиск по справочнику

**Цель:** Дать пользователю мгновенный офлайн-поиск по заголовкам и содержимому статей.
**Затрагивает:** frontend (Flutter presentation/domain)

**Задачи:**
- [ ] Реализовать поиск по заголовкам статей и их содержимому с обновлением результатов по мере ввода
- [ ] Выводить результаты с названием статьи и разделом; тап открывает статью
- [ ] Реализовать состояние пустого результата с понятным сообщением и предложением открыть оглавление
- [ ] Обеспечить работу поиска офлайн
- [ ] Написать тесты: поиск по заголовку, поиск по содержимому, открытие статьи из результата, состояние «нет результатов»

**Когда готова:** Поиск мгновенно находит статьи по заголовку и содержимому, открывает статью по тапу и корректно показывает пустой результат; тесты проходят.
