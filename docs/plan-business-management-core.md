# Plan: Полноценное ведение бизнеса (Business Management Core)

**PRD:** docs/prd-business-management-core.md
**Дата:** 2026-09-15

## Фазы реализации

### Фаза 1: Сохранность данных и сервисы старта (Tracer Bullet)

**Цель:** Приложение перестаёт затирать данные пользователя при запуске и получает сервисы для онбординга, демо-режима и полной очистки.
**Затрагивает:** database
**Задачи:**
- [x] `FirstRunService`: флаг завершённого онбординга и выбранный режим старта в локальном хранилище
- [x] Изменить демо-сид: `loadDemoData` без `clear()`, вызов только по явному действию, убрать автосид из `main.dart`
- [x] `DataResetService`: очистка всех коллекций (операции, клиенты, счета, документы, договоры, отчёты рисков, уведомления) и профиля
- [x] Тесты: данные сохраняются при повторном открытии БД; демо не грузится автоматически; очистка удаляет всё и возвращает флаг онбординга
- [x] Тесты: миграция существующей БД предыдущей версии открывается без потери данных

**Когда готова:** После перезапуска пользовательские данные не изменяются; демо-данные не загружаются без явного вызова; сервисы покрыты тестами; сборка Windows проходит без ошибок.

### Фаза 2: Онбординг (UI)

**Цель:** Первый запуск ведёт пользователя через настройку приложения и даёт выбрать режим старта.
**Затрагивает:** frontend
**Задачи:**
- [x] Экран онбординга: выбор сфер деятельности, заполнение профиля ИП, выбор «Начать с нуля / Загрузить демо-данные»
- [x] Загрузка демо-данных по действию пользователя с предупреждением о перезаписи
- [x] Полная очистка данных с подтверждением и возвратом к онбордингу
- [x] Подключение онбординга в `main.dart` / `HomeShell` по флагу первого запуска
- [x] Виджет-тесты: прохождение онбординга, оба режима старта, подтверждение очистки

**Когда готова:** Первый запуск показывает онбординг; режимы «с нуля» и «демо» работают; очистка возвращает приложение к состоянию после установки; сборка Windows проходит.

### Фаза 3: Операции — слой данных (Модуль 1)

**Цель:** Модель и репозиторий операций поддерживают доходы, расходы и полный CRUD.
**Затрагивает:** database
**Задачи:**
- [x] Расширить `Transaction`: тип (доход/расход), категория, комментарий, ссылка на клиента
- [x] Репозиторий: `getById`, `update`, `delete`, `count`, выборка по периоду/типу/сфере/клиенту
- [x] Агрегаты: доход, расход и прибыль за период; доход отдельно для лимита и налога
- [x] Тесты репозитория: CRUD, фильтры, инвалидация кэша агрегатов
- [x] Тесты агрегатов: расход не входит в лимит НПД, прибыль = доход − расход, корректность при нуле операций

**Когда готова:** CRUD операций и агрегаты покрыты тестами; доход учитывается в лимите, расход — нет.

### Фаза 4: Операции — интерфейс (Модуль 1)

**Цель:** Пользователь вручную ведёт доходы и расходы, а дашборд показывает прибыль.
**Затрагивает:** frontend
**Задачи:**
- [x] Экран «Операции»: список, фильтры (тип, сфера, период, клиент), поиск, итоги за период
- [x] Форма операции (создание/редактирование) с валидацией и выбором сферы
- [x] Удаление операции с подтверждением и отменой
- [x] Дашборд: карточка прибыли, расходы по сферам, пересчёт налога и лимита, корректное пустое состояние
- [x] Виджет-тесты: список/фильтры/поиск, форма add/edit, удаление, дашборд при нуле и с данными

**Когда готова:** Пользователь создаёт, редактирует и удаляет доход/расход; список фильтруется и ищет; дашборд показывает доход, расход и прибыль; сборка Windows проходит.

### Фаза 5: Профиль и настройки (UI, Модуль 2)

**Цель:** Пользователь редактирует свои реквизиты и настраивает приложение.
**Затрагивает:** frontend
**Задачи:**
- [x] Экран редактирования профиля ИП: ФИО, ИНН, ОГРНИП, адрес, банковские реквизиты
- [x] Экран настроек: тема, сферы деятельности, управление данными (демо/очистка), «О приложении»
- [x] Автоподстановка сохранённого профиля в новые договоры, чеки и акты
- [x] Перенос переключателя темы с дашборда в настройки
- [x] Виджет-тесты: сохранение профиля, применение настроек между запусками, подстановка реквизитов

**Когда готова:** Профиль и настройки редактируются и сохраняются; новые документы используют актуальные реквизиты; сборка Windows проходит.

### Фаза 6: Клиенты — слой данных (Модуль 3)

**Цель:** Появляется справочник контрагентов с полным CRUD.
**Затрагивает:** database
**Задачи:**
- [x] Модель `Client` (наименование, ИНН, тип юрлицо/физлицо, контакты, заметки) и схема БД
- [x] `ClientRepository`: CRUD, поиск по наименованию и ИНН
- [x] Шифрование контактов клиента при хранении
- [x] Тесты репозитория: CRUD, поиск по имени и ИНН
- [x] Тесты: удаление клиента не удаляет связанные операции и документы

**Когда готова:** CRUD клиентов покрыт тестами; связи с операциями и документами сохраняются при удалении.

### Фаза 7: Клиенты — интерфейс (Модуль 3)

**Цель:** Пользователь ведёт клиентов и выбирает их при создании документов.
**Затрагивает:** frontend
**Задачи:**
- [x] Экран справочника клиентов: список, поиск, создание, редактирование, удаление с подтверждением
- [x] Карточка клиента с историей операций и документов
- [x] Выбор клиента из справочника в формах операции, договора и чека
- [x] Виджет-тесты: справочник, карточка клиента, выбор клиента в формах

**Когда готова:** Клиент создаётся, редактируется и удаляется; его можно выбрать при создании операции, договора и чека; сборка Windows проходит.

### Фаза 8: Счета — слой данных (Модуль 4)

**Цель:** Появляется учёт счетов, статусов и оплат.
**Затрагивает:** database
**Задачи:**
- [x] Модель `Invoice`: номер, клиент, сумма, дата выставления, срок, статус, частичная оплата, ссылка на операцию
- [x] `InvoiceRepository`: CRUD, `markPaid`, выборка просроченных
- [x] Создание дохода-операции при полной оплате счёта
- [x] Тесты репозитория: CRUD, частичная оплата, создание дохода при оплате
- [x] Тесты: статус «просрочен» определяется по сроку и дате; ручная установка «просрочен» недоступна

**Когда готова:** Счета, статусы и оплаты покрыты тестами; оплата создаёт доход; просрочка считается автоматически.

### Фаза 9: Счета — интерфейс (Модуль 4)

**Цель:** Пользователь выставляет счета и контролирует дебиторскую задолженность.

**Задачи:**

- [ ] Форма счёта: создание, редактирование, удаление с подтверждением
- [ ] Действие «Отметить оплаченным» (в т.ч. частичная оплата) с созданием дохода
- [ ] Виджет-тесты: список и дебиторка, форма счёта, отметка оплаты

**Когда готова:** Счета создаются и редактируются; дебиторка и просрочка отображаются; отметка оплаты создаёт доход; сборка Windows проходит.

### Фаза 10: Отчёты, экспорт и бэкап — слой данных (Модуль 5)

**Цель:** Данные преобразуются в отчёты и файлы для выгрузки и восстановления.
**Затрагивает:** backend
**Задачи:**
- [ ] `ReportBuilder`: доход, расход, прибыль и налог за период с разбивкой по сферам и клиентам
- [ ] Экспорт операций и счетов в CSV
- [ ] Формирование PDF-отчёта с корректной кириллицей
- [ ] `BackupService`: экспорт и импорт всех данных в файл
- [ ] Тесты: расчёт отчёта, содержимое CSV, импорт бэкапа восстанавливает данные

**Когда готова:** Отчёты и файлы формируются, бэкап восстанавливается на чистой базе; всё покрыто тестами.

**Цель:** Пользователь выгружает отчётность и управляет резервными копиями.
**Затрагивает:** frontend
**Задачи:**
- [ ] Экран отчётов: выбор периода, сводки, графики, разбивка по сферам и клиентам
- [ ] Экспорт CSV и PDF с сохранением файла на устройство
- [ ] Импорт резервной копии с предупреждением о замене данных
- [ ] Виджет-тесты: отчёт за период, экспорт, импорт с подтверждением

**Когда готова:** Пользователь формирует отчёт и выгружает CSV/PDF; импорт восстанавливает данные; сборка Windows проходит.

### Фаза 12: Уведомления — движок (Модуль 6)

**Цель:** Фоновая проверка реально формирует уведомления по правилам.
**Затрагивает:** backend
**Задачи:**
- [ ] Реализовать фоновый обработчик проверок вместо заглушки
- [ ] `LimitMonitor`: пороги 80/90/95/100% и контрольные сроки 60/30 дней
- [ ] Напоминания о счетах за 3/7/14 дней и о просрочке без дублей
- [ ] Детектор аномалий операций и недельный дайджест
- [ ] Тесты: срабатывание каждого правила, отсутствие дублей, соблюдение тихих часов

**Когда готова:** Правила формируют уведомления, не дублируются и покрыты тестами.
