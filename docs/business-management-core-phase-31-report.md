# Отчёт по модулю Business Management Core (Фаза 31)

## Дата: 2026-09-16
## Ветка: feature-phase-31

## Назначение

Слой данных клиентов (Модуль 3): появляется справочник контрагентов с полным
CRUD, поиском по наименованию и ИНН и шифрованием персональных данных при
хранении. Удаление клиента не затрагивает связанные операции и документы.

## Что реализовано

| Задача | Реализация |
|--------|------------|
| Модель `Client` | `lib/data/models/client.dart`: коллекция `Client` с полями `name`, `inn`, `type` (`@enumerated ClientType`), `contacts`, `notes`, `createdAt`. Тип клиента переиспользует `ClientType` (`legal`/`individual`) из `domain/documents/my_tax_deep_link.dart`, поэтому совпадает с типом покупателя для чека «Мой налог» |
| Схема БД | `ClientSchema` добавлена в `AppDatabase.schemas` (`lib/data/database.dart`); Isar мигрирует существующую базу без потери данных |
| `ClientRepository` | `lib/data/repositories/client_repository.dart` — интерфейс: `add`, `getById`, `update`, `delete`, `count`, `getAll({search})`, `clear` |
| Реализация репозитория | `lib/data/repositories/isar_client_repository.dart`: CRUD поверх Isar, поиск по наименованию и ИНН без учёта регистра, сортировка по наименованию |
| Шифрование контактов | Строки `name`, `inn`, `contacts`, `notes` шифруются на уровне поля (AES-256, `DatabaseEncryptionService`) — как данные контрагентов в операциях и документах. Поэтому поля не индексируются, а поиск и сортировка выполняются в памяти после расшифровки |
| Связь документов с клиентом | В `Document` добавлено поле `clientId` (индекс, `0` — без привязки): связь хранится идентификатором и не каскадируется при удалении клиента |
| Полная очистка данных | `DataResetService` теперь очищает и справочник клиентов; `IsarClientRepository` создаётся в `main.dart` |

## Рабочий путь

1. Пользователь создаёт карточку клиента через `add` (позже — через UI фазы 32):
   наименование, ИНН, тип (юрлицо/физлицо), контакты, заметки.
2. `getAll({search})` отдаёт справочник, отсортированный по наименованию; поиск
   ищет подстроку по наименованию и ИНН.
3. `getById` / `update` / `delete` / `count` обеспечивают полный CRUD.
4. Операции и документы ссылаются на клиента по `clientId`; удаление клиента
   оставляет эти записи и их связи нетронутыми.
5. Полная очистка данных (`DataResetService.resetAll`) удаляет и клиентов.
