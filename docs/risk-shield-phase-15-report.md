# Отчёт по модулю Risk Shield (Фаза 15)

## Дата: 2026-09-13
## Ветка: feature-phase-15

## Назначение

Интеграция Risk Shield с генератором договоров, показ результатов автопроверки
в карточке договора до сохранения, дисклеймер и инструкция по конвертации, а
также подтверждение всех критериев готовности PRD.

## Что реализовано

| Задача | Реализация |
|--------|------------|
| Автозапуск проверки после создания договора | `ContractWizardScreen._runRiskCheck()` — при переходе на шаг предпросмотра договор анализируется `RiskAnalyzerUseCase` |
| Результаты в карточке договора | `RiskShieldSummaryCard` (`lib/presentation/risk/risk_shield_summary_card.dart`): индекс, число рисков, дисклеймер и найденные формулировки с копированием альтернатив |
| Единая карточка риска | `RiskMatchCard` (`lib/presentation/risk/risk_match_card.dart`) вынесена из `risk_report_view.dart` и переиспользуется в отчёте и в карточке договора |
| Сохранение отчёта в историю | Отчёт автопроверки сохраняется через `RiskReportRepository` при создании PDF-файла |
| Дисклеймер и инструкция PDF/DOCX→TXT | `RiskShieldInfoSheet` (`lib/presentation/risk/risk_shield_info_sheet.dart`) + дисклеймер в пустом состоянии и результатах проверки |
| Проброс зависимостей | `ContractLibraryScreen`, `ContractArchiveScreen`, `HomeShell` передают анализатор и репозиторий истории в мастер |
| Smoke-тест | `test/risk_shield_integration_smoke_test.dart` — генерация → автопроверка → результаты → копирование → сохранение |
| Критерии PRD | `test/risk_shield_prd_criteria_test.dart` — консолидированная проверка всех пунктов «Критерии готовности» |

## Интеграция с генератором

1. Пользователь заполняет мастер и переходит к предпросмотру.
2. `_runRiskCheck()` собирает документ (`ComposedContract`) и анализирует его
   встроенной базой маркеров; имя источника — имя будущего PDF.
3. Результат показывается в `RiskShieldSummaryCard` непосредственно в карточке
   договора. Пользователь может раскрыть риск, скопировать безопасную
   формулировку, вернуться к правке полей или нажать «Проверить заново».
4. При создании PDF отчёт сохраняется в историю Risk Shield.

Если анализатор не передан (например, в существующих тестах генератора),
поведение мастера не меняется — секция Risk Shield скрыта.

## Дисклеймер и конвертация

* Дисклеймер «Risk Shield не заменяет юридическую консультацию» показывается:
  в пустом состоянии вкладки «Проверка», под итогами проверки и в карточке
  договора.
* Кнопка «i» в AppBar и ссылка в пустом состоянии открывают
  `RiskShieldInfoSheet` с пошаговой инструкцией PDF/DOCX → TXT и лимитом
  100 КБ. Файлы обрабатываются локально.

## Критерии готовности PRD

| Критерий | Проверка |
|----------|----------|
| 50+ маркеров | `risk_marker_base_test`, `risk_shield_prd_criteria_test` (59 маркеров) |
| Точность > 90% | `risk_accuracy_test`, `risk_shield_prd_criteria_test` (recall 100%) |
| Ложноположительные < 5% | `risk_accuracy_test`, `risk_shield_prd_criteria_test` (0%) |
| Время анализа 30 КБ < 500 мс | `risk_analyzer_test`, `risk_shield_prd_criteria_test` |
| Индекс безопасности | `safety_index_test`, `risk_shield_prd_criteria_test` |
| Альтернативы для 100% рисков | `risk_shield_prd_criteria_test` |
| История проверок | `risk_report_repository_test`, `risk_history_screen_test` |
| Accessibility | `risk_shield_screen_test` (семантика индекса и уровней) |
| Интеграция с генератором | `risk_shield_integration_smoke_test` |

## Ручная проверка на реальном устройстве

Автоматические тесты запускаются в headless-окружении; финальную проверку на
устройстве/эмуляторе рекомендуется выполнить по шагам:

1. Создать договор в генераторе и убедиться, что на шаге предпросмотра
   появляется карточка Risk Shield с индексом и рисками.
2. Скопировать безопасную формулировку и вставить её в поле договора.
3. Создать PDF и открыть историю Risk Shield — отчёт должен присутствовать.
4. Открыть лист «Как это работает» и проверить читаемость текста и
   навигацию скринридером (TalkBack/VoiceOver).
