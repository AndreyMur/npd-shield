# Отчёт по модулю Notification & Reminder System (Фаза 21)

## Дата: 2026-09-14
## Ветка: feature-phase-21

## Назначение

Tracer Bullet системы уведомлений: рабочий путь «получение уведомления →
сохранение → просмотр в центре уведомлений». Проверяется базовая
инфраструктура (flutter_local_notifications, FCM/APNs, workmanager), модель
хранения, центр уведомлений с группировкой, фильтрами, статусами и удалением.

## Что реализовано

| Задача | Реализация |
|--------|------------|
| Локальные уведомления | `NotificationService` (`lib/data/notifications/notification_service.dart`) — абстракция разрешений, показа и отмены; `FlutterLocalNotificationService` на базе `flutter_local_notifications` с обработкой неподдерживаемых платформ; `NoopNotificationService` для тестов |
| Push-инфраструктура (FCM/APNs) | `PushNotificationService` и `FirebasePushNotificationService` (`lib/data/notifications/`): инициализация Firebase, разрешение, токен, подписка на темы, поток входящих сообщений; при отсутствии конфигурации (например, Windows) переходит в недоступное состояние, не роняя приложение |
| Преобразование push в уведомление | `push_notification_payload.dart`: разбор `type/title/body/payload/actionLabel` с запасными значениями из блока `notification` FCM и защитой от рассинхронизации версий |
| Фоновые задачи (workmanager) | `NotificationBackgroundScheduler` (`lib/data/notifications/notification_background_scheduler.dart`): точка входа `notificationBackgroundDispatcher` с `@pragma('vm:entry-point')`, периодическая задача, отмена; `Noop`-заглушка для платформ без поддержки |
| Isar-коллекция уведомлений | `AppNotification` (`lib/data/models/app_notification.dart`): тип, статус, заголовок, текст, дата, payload, подпись действия; индексы по типу, статусу и дате; схема добавлена в `AppDatabase` |
| Репозиторий центра | `NotificationRepository` и `IsarNotificationRepository` (`lib/data/repositories/`): сохранение, выборки по типу и статусу, счётчик непрочитанных, пометка прочтения, удаление, очистка истории старше 30 дней |
| Домен центра | `notification_center.dart` (`lib/domain/notifications/`): фильтрация по типу, статусу, диапазону дат и запросу, сортировка, группировка по дате (сегодня/вчера/на этой неделе/ранее), подсчёт непрочитанных, удаление старше 30 дней |
| Центр уведомлений (UI) | `NotificationCenterScreen` и `NotificationCard` (`lib/presentation/notifications/`): список с иконками по типам, группировка, фильтры по типу/статусу/дате, пометка прочитано/непрочитано, кнопка действия, удаление с отменой, пустое и ошибочное состояния, семантические метки для скринридеров |
| Интеграция в приложение | `main.dart` инициализирует локальные/push/фоновые каналы; `HomeShell` получил раздел «Уведомления» со значком непрочитанных; демо-история засевается при первом запуске (`seedNotifications`) |

## Рабочий путь

1. Уведомление приходит локально (или через FCM/APNs) и преобразуется в
   `AppNotification`.
2. Запись сохраняется в Isar-коллекцию центра уведомлений.
3. Пользователь открывает раздел «Уведомления»: список группируется по дате,
   фильтруется по типу, статусу и периоду, показывает значок непрочитанных.
4. Нажатие на карточку отмечает уведомление прочитанным и отменяет системное;
   кнопка действия запускает связанное действие (например, «Отметить как
   оплаченный»); меню карточки позволяет сменить статус и удалить уведомление
   с возможностью отмены.
5. История старше 30 дней автоматически вычищается при открытии центра.

## Ручная проверка на реальном устройстве

Автоматизированные тесты покрывают путь и логику без устройства. Для полного
подтверждения PRD требуется ручной прогон на Android/iOS:

1. Разрешить уведомления и убедиться, что системное уведомление отображается.
2. Отправить тестовое FCM-сообщение и проверить, что оно попало в центр.
3. Проверить скринридером карточки, фильтры и кнопку действия.
4. Убедиться, что фоновая задача зарегистрирована и выполняется.
