# Plan: Notification & Reminder System

**PRD:** prd-notification-system
**Дата:** 2026-08-31

## Фазы реализации

### Фаза 21: Tracer Bullet — Базовая инфраструктура уведомлений и центр уведомлений

**Цель:** Рабочий путь «настройка уведомлений → получение локального push → просмотр в центре уведомлений». Проверка основной инфраструктуры (flutter_local_notifications, FCM/APNs, workmanager).
**Затрагивает:** frontend (Flutter) / backend (пуш-инфраструктура)
**Задачи:**
- [ ] Интегрировать локальные уведомления (flutter_local_notifications) и push-инфраструктуру (FCM для Android / APNs для iOS).
- [ ] Интегрировать фоновые задачи через workmanager для периодической проверки условий.
- [ ] Создать Isar-коллекцию `Notification` (тип, заголовок, текст, дата, status прочитано/непрочитано) с миграциями для центра уведомлений.
- [ ] Реализовать центр уведомлений: список с иконками по типам, карточка (заголовок, текст, время, кнопки действий), группировка и фильтрация по дате и типу, пометка прочитано/непрочитано, удаление.
- [ ] Написать unit-тесты для репозитория уведомлений и widget-тесты для центра уведомлений (список, фильтрация, статусы, удаление, accessibility для скринридеров).
**Когда готова:** Уведомления доставляются локально и через FCM/APNs и сохраняются; центр уведомлений показывает историю за последние 30 дней с группировкой, фильтрацией, статусами и удалением; элементы доступны для скринридеров.

### Фаза 22: Настройки уведомлений

**Цель:** Пользователь управляет типами, частотой и тихим режимом уведомлений.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [ ] Реализовать настройки включения/выключения каждого типа уведомлений (лимит, счета, аномалии, дайджест).
- [ ] Реализовать настройку времени «Тихий режим» (по умолчанию 22:00 - 08:00), при котором уведомления не отправляются.
- [ ] Реализовать выбор порогов для уведомлений о лимите и частоту напоминаний о счетах.
- [ ] Сохранить настройки в Isar и применять их при отправке уведомлений.
- [ ] Написать unit-тесты для сохранения/применения настроек и widget-тесты для экрана настроек (переключатели с описаниями).
**Когда готова:** Настройки уведомлений сохраняются и применяются; тихий режим (22:00-08:00) блокирует отправку; пороги лимита и частота напоминаний настраиваются.

### Фаза 23: Уведомления о лимите и напоминания о счетах

**Цель:** Проактивные уведомления о приближении к лимиту 2.4 млн и напоминания о неоплаченных счетах.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [ ] Реализовать мониторинг дохода относительно лимита и уведомления при порогах 80%, 90%, 95%, 100% и за 60, 30 дней до прогнозируемого исчерпания.
- [ ] Сформировать текст уведомления о лимите: «До лимита осталось X руб. (Y дней)».
- [ ] Реализовать отслеживание статуса оплаты счетов (оплачен/неоплачен) и напоминания через 3, 7, 14 дней после выставления, включая напоминание о просроченном платеже.
- [ ] Реализовать кнопку «Отметить как оплаченный» в уведомлении о счёте.
- [ ] Написать unit-тесты для логики порогов лимита (80%, 90%, 95%, 100%, 60/30 дней), напоминаний о счетах (3/7/14 дней, просрочка) и widget-тесты для кнопки «Отметить как оплаченный».
**Когда готова:** Push-уведомления о лимите доставляются за 60, 30 дней и при 80% (и 90/95/100%); напоминания о неоплаченных счетах отправляются через 3, 7, 14 дней и при просрочке; кнопка «Отметить как оплаченный» обновляет статус; уведомления не отправляются в ночное время по настройке.

### Фаза 24: Предупреждения об аномалиях и еженедельный дайджест

**Цель:** Детекция нестандартных транзакций и формирование еженедельного дайджеста.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [ ] Реализовать определение аномалий: сумма превышает среднюю в 3+ раза, новый контрагент с крупной суммой, транзакция в необычное время.
- [ ] Сформировать уведомление об аномалии с описанием и рекомендацией по проверке, в реальном времени.
- [ ] Реализовать еженедельный дайджест (формирование каждое воскресенье в 10:00): доход за неделю, налог, остаток до лимита, количество сделок.
- [ ] Реализовать push с rich-контентом для дайджеста и кнопками «Подробнее», «Сформировать отчёт».
- [ ] Написать unit-тесты для детекции аномалий (3 правила) и формирования дайджеста (содержание, расписание) и widget-тесты для rich-уведомления.
**Когда готова:** Аномалии определяются и уведомляются в реальном времени; еженедельный дайджест формируется каждое воскресенье в 10:00 с доходом, налогом, остатком до лимита и числом сделок, отправляется с кнопками действий.

### Фаза 25: Надёжность, безопасность и финализация

**Цель:** Подтвердить нефункциональные требования (доставка < 1 минуты, безопасность данных, работа без сети) и все критерии готовности PRD.
**Затрагивает:** frontend (Flutter) / backend (пуш-инфраструктура)
**Задачи:**
- [ ] Гарантировать, что уведомления не содержат конфиденциальных данных (суммы, реквизиты) и имеют текстовые метки для скринридеров.
- [ ] Обеспечить доставку уведомлений в течение 1 минуты после наступления условия и работу при кратковременной потере сети.
- [ ] Добавить мягкое напоминание о важности включения уведомлений и инструкцию по настройке доставки на устройстве.
- [ ] Провести полный smoke-тест всех типов уведомлений end-to-end (лимит, счета, аномалии, дайджест, тихий режим, настройки).
- [ ] Проверить все критерии готовности PRD (уведомления о лимите, напоминания 3/7/14 дней, аномалии в реальном времени, дайджест по расписанию, сохранение настроек, история за 30 дней, тихий режим, accessibility) на реальном устройстве.
**Когда готова:** Все критерии готовности PRD выполнены: доставка < 1 минуты, уведомления без конфиденциальных данных и доступны для скринридеров, работают при потере сети; тихий режим и настройки работают; все типы уведомлений подтверждены smoke-тестом и тестами.
