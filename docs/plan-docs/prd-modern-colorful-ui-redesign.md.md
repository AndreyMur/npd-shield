# Plan: Modern Colorful UI Redesign

**PRD:** docs/prd-modern-colorful-ui-redesign.md
**Дата:** 2026-09-17

## Фазы реализации

### Фаза 1: Tracer Bullet — Дизайн-токены, базовая тема и дашборд

**Цель:** Минимальный рабочий путь «дизайн-токены → тема → реальный экран». Проверка гипотезы, что единая токен-система применяется без изменения API `AppTheme` и без поломки Dynamic Color.
**Затрагивает:** frontend (Flutter) / core theme
**Задачи:**
- [ ] Определить слой токенов: семантические цвета (primary, secondary, accent, surface, muted, border, destructive, warning, success) отдельно для light и dark; spacing-шкала 4/8 dp; radius-шкала (карточки 16–20, кнопки/поля 12–16, чипы — pill); elevation-шкала.
- [ ] Определить градиентные токены: брендовый (primary→secondary), доход (success), риск (warning→danger), лимит (success→warning→danger) и токены цветов сфер (IT `#2196F3`, Логистика `#FF9800`, «Все» — брендовый градиент).
- [ ] Интегрировать токены в `AppTheme` (light/dark) с сохранением публичного API; Dynamic Color остаётся опциональным слоем и не переопределяет семантические цвета риска/успеха.
- [ ] Перевести дашборд на токены: метрические карточки с акцентной типографикой, градиентная шкала лимита, цветовые акценты сфер; убрать хардкод-цвета и произвольные размеры.
- [ ] Написать unit-тесты токенов и темы (значения, контраст light/dark, приоритет семантических цветов над Dynamic Color) и widget-тесты дашборда (обе темы, 0 транзакций, переключение сфер).
**Когда готова:** Приложение собирается; дашборд отображается в обеих темах только через токены; Dynamic Color не переопределяет семантические цвета; на дашборде нет хардкод-цветов; `flutter analyze` без новых ошибок, существующие тесты проходят.

### Фаза 2: Типографика, иконография и motion-язык

**Цель:** Дать приложению фирменную типографику с кириллицей, единый стиль иконок и предсказуемый motion-язык.
**Затрагивает:** frontend (Flutter) / assets / core theme
**Задачи:**
- [ ] Подключить шрифты как ассеты: Inter (только используемые веса) для заголовков и текста, JetBrains Mono для числовых метрик; обеспечить кириллицу и корректный fallback.
- [ ] Определить и применить типо-шкалу (display, headline, title, body, label, metric) с фиксированными размерами и line-height; базовый текст 16 pt, line-height 1.5.
- [ ] Ввести дисциплину иконок: токены размеров, единое семейство (Material Symbols), filled для выбранного / outline для невыбранного, без эмодзи как структурных иконок.
- [ ] Определить motion-токены: длительности 150–300 мс, ease-out на вход / ease-in на выход, отклик микро-взаимодействий 80–150 мс, флаг reduced-motion, сводящий анимации к мгновенному переходу.
- [ ] Написать тесты: unit-тесты motion-токенов и reduced-motion, golden-тесты типо-шкалы (кириллица), widget-тесты корректной отрисовки иконок.
**Когда готова:** Шрифты с кириллицей отображаются в приложении; типо-шкала и размеры иконок берутся из токенов; при включённом reduced-motion анимации отключаются; golden-тесты подтверждают типографику.

### Фаза 3: Библиотека базовых компонентов и состояний

**Цель:** Единый набор переиспользуемых компонентов, на который переводятся все экраны.
**Затрагивает:** frontend (Flutter) / presentation (shared components)
**Задачи:**
- [ ] Реализовать варианты карточек: обычная, акцентная (градиентная), метрическая.
- [ ] Реализовать кнопки: primary (градиент), secondary, text, destructive; состояния pressed/disabled/focus без сдвига layout.
- [ ] Реализовать поля ввода с label, hint, helper и error; состояния focus/error/disabled.
- [ ] Реализовать чипы и сегмент-контролы с поддержкой цветов сфер, а также статусные баннеры info/success/warning/danger.
- [ ] Реализовать единые состояния empty, loading (skeleton/shimmer) и error; покрыть компоненты widget- и golden-тестами, включая touch-target ≥48×48 dp и pressed-state.
**Когда готова:** Компоненты доступны как общий набор; каждый вариант и состояние покрыт тестами; touch-target ≥48×48 dp и явный pressed-state подтверждены; минимум один экран уже использует компоненты.

### Фаза 4: Редизайн экранов операций и данных

**Цель:** Перевести на дизайн-систему экраны ежедневных операций с данными и списками.
**Затрагивает:** frontend (Flutter) / presentation
**Задачи:**
- [ ] Перевести на токены и компоненты экраны «Операции» и форму транзакции.
- [ ] Перевести экраны «Клиенты» (список, детали, форма) и «Счета» (список, форма).
- [ ] Перевести архив «Документы» и центр «Уведомления».
- [ ] Привести к единому виду состояния empty/loading/error на всех перечисленных экранах; обеспечить semantic labels и pressed-state.
- [ ] Обновить/написать widget-тесты для перечисленных экранов (обе темы, состояния, отсутствие хардкод-цветов) и убедиться, что существующие тесты проходят.
**Когда готова:** Экраны операций, клиентов, счетов, документов и уведомлений используют общие токены и компоненты; состояния empty/loading/error единообразны; тесты проходят в обеих темах.

### Фаза 5: Редизайн договоров, Risk Shield, отчётов и графиков

**Цель:** Перевести на дизайн-систему юридические и аналитические разделы, включая визуализации.
**Затрагивает:** frontend (Flutter) / presentation
**Задачи:**
- [ ] Перевести на токены и компоненты «Шаблоны» и «Договоры» (библиотека, архив, формы).
- [ ] Переработать Risk Shield: уровни риска различаются одновременно цветом, иконкой и текстом; индекс безопасности визуализирован по новой шкале.
- [ ] Перевести экран «Отчёты» и графики `fl_chart` на новую палитру с читаемыми легендами и tooltips.
- [ ] Обеспечить корректность графиков и статусов риска в обеих темах (контраст, различимость разделителей и состояний).
- [ ] Написать widget-тесты для экранов договоров, Risk Shield и отчётов, включая проверку различимости уровней риска по цвету+иконке+тексту и тесты графиков в обеих темах.
**Когда готова:** Разделы договоров, Risk Shield и отчётов используют токены; уровни риска различимы цветом, иконкой и текстом; графики читаемы в обеих темах; тесты проходят.

### Фаза 6: Онбординг, навигация, адаптив, доступность и производительность

**Цель:** Закрыть все оставшиеся критерии готовности: онбординг, навигационная оболочка, адаптив, доступность и p95 кадра.
**Затрагивает:** frontend (Flutter) / presentation
**Задачи:**
- [ ] Перевести онбординг (фирменные градиентные акценты, прогресс шагов), экран загрузки и «Настройки» на дизайн-систему.
- [ ] Обновить навигационную оболочку (нижняя панель и боковая навигация) под токены и motion-переходы 150–300 мс.
- [ ] Провести адаптив-проверку: 375 px, крупный телефон, планшет, портрет и ландшафт; адаптивные gutters и safe areas; desktop-режим наследует систему.
- [ ] Провести финальный accessibility-проход: контраст ≥4.5:1 / ≥3:1 в обеих темах, максимальный системный размер шрифта без поломки верстки, semantic labels, reduced-motion.
- [ ] Провести профилирование и устранить узкие места (p95 кадра < 16 мс); написать widget/golden-тесты адаптивных breakpoint-ов и крупного шрифта, обновить существующие тесты, прогнать `flutter analyze`.
**Когда готова:** Все критерии готовности PRD выполнены: единый стиль на всех 11 разделах, онбординге и экране загрузки; обе темы проходят проверку контраста; reduced-motion и крупный шрифт не ломают верстку; p95 кадра < 16 мс; `flutter analyze` без новых ошибок, все тесты проходят.
