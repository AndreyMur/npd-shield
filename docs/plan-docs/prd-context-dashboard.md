# Plan: Context Dashboard with Activity Separation

**PRD:** docs/prd-context-dashboard
**Дата:** 2026-08-31

## Фазы реализации

### Фаза 1: Tracer Bullet — Локальная модель данных и минимальный дашборд

**Цель:** Рабочий путь «ввод транзакции → отображение дохода и налоговой сводки на дашборде». Проверка основной гипотезы и базовая архитектура offline-first.
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [x] Создать Isar-коллекции `Transaction` (amount, date, sphere, clientName, clientInn) и схему базы данных с миграциями.
- [x] Внедрить тёмную и светлую тему (Material 3) с поддержкой Dynamic Color на Android 12+.
- [x] Реализовать главный экран дашборда: карточки сфер (IT / Логистика) с суммарным доходом за месяц и за год.
- [x] Реализовать переключатель «Все / IT / Логистика» с фильтрацией данных одним тапом.
- [x] Написать unit-тесты для репозиториев транзакций (суммирование по сфере и периоду) и widget-тесты для экрана дашборда при 0 транзакций и с данными.
**Когда готова:** Дашборд загружается и показывает корректные суммы дохода (за месяц и год) по каждой сфере и в целом за < 1 секунды; переключение сфер работает < 100 мс; верстка коррекктно работает в тёмной и светлой теме; дашборд корректно отображается при 0 транзакциях.

### Фаза 2: Индикатор лимита с прогнозом исчерпания

**Цель:** Пользователь видит, сколько осталось до лимита 2.4 млн и через сколько дней при текущем темпе, с цветовой шкалой.
**Затрагивает:** frontend (Flutter) / domain logic
**Задачи:**
- [ ] Реализовать расчёт лимита: текущее значение относительно 2.4 млн, цветовая кодировка (зелёный < 70%, жёлтый 70-90%, красный > 90%), текстовый прогноз «до лимита осталось X руб. (Y дней)».
- [ ] Реализовать прогноз исчерпания на основе среднего дохода за последние 3 месяца.
- [ ] Отобразить визуальную шкалу (прогресс-бар) с градиентом зелёный-жёлтый-красный на дашборде.
- [ ] Вывести показатель погрешности и дисклеймер о том, что прогноз не учитывает сезонность.
- [ ] Написать unit-тесты для расчёта лимита и прогноза (граничные значения 0%, 70%, 90%, 100%, прогноз на горизонте 3 месяцев точностью ±15 дней).
**Когда готова:** Индикатор и прогноз корректно рассчитываются и отображаются; точность прогноза ±15 дней на горизонте 3 месяцев; погрешность и дисклеймер показаны в UI; тесты покрывают граничные случаи.

### Фаза 3: Налоговый калькулятор

**Цель:** Пользователь видит сумму налога к уплате с учётом страховых взносов ИП.
**Затрагивает:** frontend (Flutter) / domain logic
**Задачи:**
- [ ] Реализовать расчёт налога 6% от дохода с вычетом фиксированной части страховых взносов ИП.
- [ ] Отобразить сумму к уплате за текущий период на дашборде.
- [ ] Учесть налоговое поле (константы в core/constants: лимит 2.4 млн, ставка 6%).
- [ ] Написать unit-тесты для калькулятора: точность ±1% от расчёта ФНС, вычет взносов, граничные случаи (0 дохода, достижение лимита).
**Когда готова:** Сумма налога корректно рассчитывается с точностью ±1% от расчёта ФНС и отображается за текущий период; тесты покрывают расчёт налога и вычет взносов.

### Фаза 4: Графики доходов и выбор периода

**Цель:** Пользователь видит динамику доходов по месяцам с разделением по сферам.
**Затрагивает:** frontend (Flutter)
**Задачи:**
- [ ] Реализовать линейный график доходов по месяцам (последние 12 месяцев) с помощью fl_chart.
- [ ] Реализовать раздельную визуализацию линий по сферам (IT — синий, Логистика — оранжевый).
- [ ] Реализовать выбор периода: неделя / месяц / квартал / год.
- [ ] Обеспечить Accessibility: семантические метки на графике для скринридеров.
- [ ] Написать widget-тесты для графика (корректные точки данных по периоду и сфере, переключение периода).
**Когда готова:** График корректно отображает доходы за последние 12 месяцев с разделением по сферам; переключение периода работает; график доступен для скринридеров.

### Фаза 5: Производительность, масштабируемость и оптимизация

**Цель:** Гарантировать заявленные нефункциональные требования (загрузка < 1 с, FPS ≥ 60, работа с 10 000 транзакций).
**Затрагивает:** frontend (Flutter) / database (Isar)
**Задачи:**
- [ ] Оптимизировать запросы к Isar для базы до 10 000 транзакций (индексация по дате и сфере, кэш агрегаций).
- [ ] Включить шифрование локальной БД (AES-256) в соответствии с требованиями безопасности.
- [ ] Провести профилирование: время загрузки < 1 секунды и FPS ≥ 60 на устройстве среднего класса.
- [ ] Провести smoke-тест всего дашборда end-to-end (ввод, переключение, график, налог, лимит).
- [ ] Устранить выявленные узкие места по производительности.
**Когда готова:** Время загрузки дашборда < 1 секунды, FPS ≥ 60 на среднем устройстве; база 10 000 транзакций не деградирует в производительности; БД шифруется AES-256; все критерии готовности PRD выполнены и подтверждены тестами.
