# Отчёт по модулю Business Management Core (Фаза 26)

## Дата: 2026-09-15
## Ветка: feature-phase-26

## Назначение

Tracer Bullet владения данными: приложение перестаёт затирать данные
пользователя при запуске и получает сервисы для онбординга, загрузки
демо-данных и полной очистки. Проверяется сохранность данных при повторном
открытии базы, отсутствие автоматического демо-сида и миграция существующей
базы предыдущей версии.

## Что реализовано

| Задача | Реализация |
|--------|------------|
| Флаг онбординга и режим старта | `FirstRunService` (`lib/data/services/first_run_service.dart`): абстракция + `SharedPrefsFirstRunService`; хранит `onboarding_completed` и `onboarding_start_mode` в `SharedPreferences`; enum `StartMode` (`fromScratch` / `demo`) с безопасным разбором значения |
| Демо-сид без очистки | `seedDashboardData` → `seedDemoTransactions`, `seedNotifications` → `seedDemoNotifications` (`lib/data/seed_data.dart`); убран вызов `clear()`, добавлен параметр `now` для детерминированных тестов; `loadDemoData` (`lib/data/demo_data.dart`) загружает операции, уведомления и демо-профиль по явному действию |
| Отмена автосида | Из `main.dart` удалены вызовы `seedDashboardData`, `seedNotifications` и `profileRepository.seedDemoIfEmpty`; встроенные шаблоны и маркеры риска продолжают засеваться (это данные приложения, не пользователя) |
| Полная очистка данных | `DataResetService` (`lib/data/services/data_reset_service.dart`): очищает операции, документы, черновики договоров, отчёты рисков, уведомления и профиль, затем сбрасывает состояние онбординга |
| Удаление авто-демо профиля | Из `ContractorProfileRepository` убран метод `seedDemoIfEmpty`; демо-профиль ставится только внутри `loadDemoData` |
| Схемы БД для тестов | `AppDatabase.schemas` (`lib/data/database.dart`) вынесен в публичный геттер, чтобы тесты открывали ту же схему, что и приложение |

## Рабочий путь

1. Приложение запускается: открывает базу и засевает только встроенные
   справочники (шаблоны, маркеры риска). Пользовательские коллекции не
   трогаются — данные, введённые ранее, остаются на месте.
2. Онбординг (фаза 2) читает `FirstRunService`: если он не пройден —
   показывает настройку и выбор режима старта.
3. При выборе «Загрузить демо-данные» вызывается `loadDemoData`, который
   добавляет демо к текущим данным, не удаляя их.
4. При выборе «Очистить все данные» `DataResetService.resetAll()` удаляет все
   пользовательские записи и профиль и возвращает флаг онбординга — приложение
   снова выглядит как после установки.

## Критерии готовности PRD (модуль 0, частично)

| Критерий | Проверка |
|----------|----------|
| При запуске приложение не изменяет и не удаляет данные | `database_lifecycle_test` (повторное открытие сохраняет данные), `demo_data_test` (демо не очищает) |
| Демо-данные загружаются только по явному действию | `database_lifecycle_test` (открытие базы не наполняет её), отсутствие автосида в `main.dart` |
| Очистка удаляет все сущности и профиль | `data_reset_service_test` |
| Факт завершения онбординга сохраняется между запусками | `first_run_service_test` |
| Миграция схемы не повреждает существующую БД | `database_lifecycle_test` (база предыдущей версии открывается без потери данных) |
