# Отчёт по модулю Business Management Core (Фаза 33)

## Дата: 2026-09-16
## Ветка: feature-phase-33

## Назначение

Слой данных счетов (Модуль 4): появляется учёт выставленных счетов, их статусов
и оплат. Счёт ссылается на клиента из справочника, поддерживает частичные оплаты,
автоматически определяется как просроченный по сроку оплаты, а при полной оплате
создаёт доход-операцию, которая учитывается в лимите НПД и налоге.

## Что реализовано

| Задача | Реализация |
|--------|------------|
| Модель `Invoice` | `lib/data/models/invoice.dart`: номер, клиент (`clientId` + шифруемые `clientName`/`clientInn`), сумма, дата выставления (`issuedAt`), срок (`dueDate`), статус, частичная оплата (`paidAmount`/`paidAt`), ссылка на операцию (`transactionId`), комментарий. Вычисляемые `outstanding`, `isFullyPaid`, `effectiveStatus`, `isOverdue` |
| Статусы счёта | `InvoiceStatus`: `draft`, `sent`, `paid`, `overdue`, `cancelled`. «Просрочен» не хранится в базе и исключён из `InvoiceStatus.manualValues` |
| `InvoiceRepository` | `lib/data/repositories/invoice_repository.dart`: CRUD, `getByClientId`, `getOverdue`, `getOutstandingTotal`, `markPaid` |
| Реализация репозитория | `lib/data/repositories/isar_invoice_repository.dart`: CRUD поверх Isar, шифрование персональных полей (AES-256), отметка оплаты, выборка просроченных, суммарная дебиторка |
| Создание дохода | `markPaid` при полной оплате переводит счёт в `paid` и создаёт доход-`Transaction` (тип `income`, сумма счёта, дата оплаты, клиент, сфера) через `TransactionRepository`; `id` операции сохраняется в `transactionId` |
| Просрочка | `Invoice.effectiveStatus` возвращает `overdue` для отправленного счёта, если срок оплаты раньше начала текущего дня; оплаченные, отменённые и черновики просроченными не становятся |
| Запрет ручного «просрочен» | `add`/`update` бросают `ArgumentError` при статусе `overdue`; в базе просроченный счёт хранится как `sent` |
| Схема БД | `InvoiceSchema` зарегистрирована в `AppDatabase.schemas` (`lib/data/database.dart`) |
| Очистка данных | `DataResetService` получил `InvoiceRepository` и очищает счета; `main.dart` создаёт `IsarInvoiceRepository` и передаёт его в сервис |

## Рабочий путь

1. Счёт создаётся и редактируется с номером, клиентом, суммой, датой выставления и
   сроком оплаты; статус выбирается из ручных значений (`draft`, `sent`, `paid`,
   `cancelled`).
2. Просрочка не выставляется вручную: счёт с истёкшим сроком автоматически
   считается просроченным при чтении (`effectiveStatus`), а `getOverdue` возвращает
   такие счета, отсортированные по сроку.
3. Частичная оплата уменьшает остаток (`outstanding`) и накапливается в
   `paidAmount`, не меняя статус.
4. Полная оплата (`markPaid` без суммы или суммой остатка) переводит счёт в
   `paid` и один раз создаёт доход-операцию; повторная оплата ничего не меняет.
5. `getOutstandingTotal` даёт суммарную дебиторскую задолженность по выставленным
   счетам (черновики и отменённые не учитываются).
