# Plan: Адаптивная верстка для телефона — меню-drawer и горизонтальный слайдер сфер

**PRD:** prd-mobile-adaptive-layout-drawer-menu-spheres-slider
**Дата:** 2026-09-18

## Фазы реализации

### Фаза 1: Сквозной путь — меню-drawer вместо нижней панели на телефоне

**Цель:** Дать рабочий минимальный путь: на телефоне пользователь открывает меню с Дашборда, переходит в любой из 11 разделов, а на широких экранах ничего не меняется.
**Затрагивает:** frontend / UI

**Задачи:**
- [x] Отключить нижнюю панель `NavigationBar` при ширине < 900 px, сохранив текущее переключение разделов через `IndexedStack` и индекс `_selectedIndex`.
- [x] Добавить боковое меню-drawer со всеми 11 разделами в текущем порядке: «иконка + текст», уменьшенный единый шрифт; иконка контурная/заполненная по активности, как в текущей навигации.
- [x] Добавить точку входа в меню (гамбургер) в шапку Дашборда как сквозной путь; выделять активный раздел в меню.
- [x] Реализовать выбор раздела (закрытие меню + переключение экрана) и закрытие меню системной кнопкой «Назад» без закрытия приложения.
- [x] Тесты сквозного пути: на ширине < 900 px нет `NavigationBar`; меню содержит все 11 пунктов; выбор пункта переключает экран; «Назад» закрывает меню; на ширине >= 900 px `NavigationRail` отображается без изменений.

**Когда готова:** На телефоне с Дашборда можно открыть меню, увидеть все 11 разделов и перейти в любой из них; на десктопе поведение навигации не изменилось.

### Фаза 2: Меню на всех экранах, счётчик уведомлений и темы

**Цель:** Сделать меню доступным с любого экрана и довести его до требований по счётчику непрочитанных, темам и доступности.
**Затрагивает:** frontend / UI

**Задачи:**
- [ ] Добавить точку входа в меню (гамбургер) в шапки остальных 10 экранов разделов, чтобы меню открывалось отовсюду.
- [ ] Показывать счётчик непрочитанных у пункта «Уведомления» при значении > 0, сохранив текущую логику `_unreadCount` и индекс «Уведомления».
- [ ] Обеспечить корректный вид меню в светлой и тёмной темах через существующие токены.
- [ ] Обеспечить доступность меню: интерактивная область пунктов не меньше 48×48 dp, подписи читаемы скринридерами.
- [ ] Тесты: гамбургер доступен на всех 11 экранах; счётчик отображается при > 0 и скрыт при 0; меню корректно в светлой и тёмной темах.

**Когда готова:** С любого экрана на телефоне открывается меню, счётчик непрочитанных виден, светлая и тёмная темы отображаются корректно.

### Фаза 3: Горизонтальный слайдер сфер на дашборде

**Цель:** Заменить переполняющийся фильтр сфер на горизонтально прокручиваемый список, доступный на узких экранах.
**Затрагивает:** frontend / UI

**Задачи:**
- [ ] Заменить `SegmentedButton<DashboardFilter>` на горизонтально прокручиваемый список компактных чипов «Все / IT / Логистика» с иконкой и подписью.
- [ ] Выделять активный чип акцентным цветом, неактивные — нейтральным; добавить признак прокручиваемости (частично видимый следующий чип).
- [ ] Сохранить текущую логику пересчёта дашборда при выборе сферы (состав `DashboardFilter` и поведение не меняются).
- [ ] Тесты: слайдер прокручивается по горизонтали, все три значения доступны и меняют данные идентично прежнему поведению; нет переполнения на ширине 320 px; корректность в светлой и тёмной темах.
- [ ] Обновить существующие тесты, ссылающиеся на `SegmentedButton<DashboardFilter>` (`dashboard_screen_test`, `dashboard_smoke_test`).

**Когда готова:** Фильтр сфер на дашборде — горизонтальный слайдер; выбор сферы пересчитывает данные так же, как раньше; существующие тесты дашборда проходят.
